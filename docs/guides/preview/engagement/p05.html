The Jira token — done

Connected on a scoped read-only token. Kept for reference, and for the next person.

Connected

Your token is the scoped read-only kind — the better one, and the one you said was all this account could issue. It took a change to the program rather than a downgrade to your token, which was the right way round.

Nothing is configured yet, and that is expected. Test connection proves the credential; it saves nothing. Choosing which Jira fields carry the organization and the use case is a later sitting, and I will walk you through it.
1
Go to id.atlassian.com/manage-profile/security/api-tokens and choose Create API token with scopes — the read-only kind.
2
Tick only the read ones — the scopes beginning read:, for Jira work and Jira users. Nothing saying write:, manage: or delete:. The label Atlassian asks for is only a name on its own list and is used nowhere else. The token appears once. Copy it somewhere safe before closing the page.
3
In Supabase: Edge Functions → Secrets → Add new secret. Do this three times. The Name must be typed exactly as printed here — it is not a label you choose:
JIRA_BASE_URL https://your-site.atlassian.net JIRA_EMAIL the Atlassian account email JIRA_API_TOKEN the token from step 2
Three separate secrets, not one. Just the site in the URL — nothing after .net.

The mistake this step invites

The names on the left are fixed. The program looks for those three words and nothing else — give a secret any other name and it is invisible, however correct its value is. In particular do not name a secret after the label you gave the token at Atlassian; that label lives only on Atlassian's own list.

If Test connection says a secret is missing, this is almost always why. Go back to the secrets list and check the three names character for character.
4
Wait for me to say the program is ready — see the next page. Then in the app: Settings → Jira → Test connection. Green, naming the account and site it signed in as. Red names exactly which of the three secrets is wrong — it never shows you the value.

Nothing is written to Jira, ever

The read-only guarantee here is ours, not the token's: the program can call four Jira addresses and no others, and its own tests check that by reading its source code, so a change that allowed writing would fail the build. You get a preview of what it read and what it matched to; nothing changes on either side.
