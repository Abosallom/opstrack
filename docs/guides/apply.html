Everything else is already live, including last night's work: every hospital now carries all eleven use cases, and the detail panel opens with them. Open nphiescore.com. If a small bar appears saying “A new version is available” with a Reload button, press it.

You should then see: the map drawing one box at the top reading 140, with six departments under it and no panel covering the picture. All six now read in Arabic:

Then try these three, which are new since last night. Press + four times: the cards should keep growing rather than dying after two presses. Tap a department: its hospitals appear. Step 2 — run 0032

2

5 minThe use-case ladder

Open supabase/migrations/0032_use_case_rungs.sql in the repository. Select all of it, copy, paste into the editor, and press Run.

It adds the ladder each use case climbs — Intake → DEV → STG/TEST → COC → PROD — the ability to mark a use case not applicable to a hospital, the blocked flag with who you are waiting on, the four columns the COC chase needs, and an append-only log of every rung change.

That log is the one that matters most: it is what will finally let the app answer “what moved this week”, which nothing in this product has ever been able to say.

Success looks like: “Success. No rows returned.” It gives a rung to all 1,540 use-case rows — 140 hospitals × eleven use cases, the grid that was filled last night. The file ends in four checks: eleven visible use cases, every row given a rung, no row left pointing at a hidden use case, and the change log having recorded something. If any check fails it raises an error naming which one, and nothing is committed.
افتح الملف المذكور أعلاه، وانسخ محتواه كاملًا، والصقه في المحرّر، ثم اضغط Run. يضيف هذا الملف سُلّم المراحل لكل حالة استخدام، وإمكانية تعليم حالة بأنها «لا تنطبق» على منشأة معيّنة، وعلامة التعليق مع تحديد الجهة المنتظَرة، وأعمدة متابعة شهادة الإنجاز، وسجلًّا لكل تغيير في المرحلة. النجاح يظهر كرسالة «Success. No rows returned».

4

3 minThe HIS catalogue

supabase/migrations/0034_his_catalogue.sql — same again.

Eleven hospital information systems, every name taken from strings your own data already carries. Rhapsody is deliberately not among them — it is the engine your technical team builds interfaces in, not something a hospital runs, and including it would tag most of the estate with one meaningless value.

Expect: eleven rows in the new his_products table, and every one of your 140 hospitals showing no system recorded. That is correct, not a failure: this file creates the catalogue and the column and deliberately fills in nobody. Your own data names an HIS for only sixteen hospitals, and each of those sixteen is a proposal for you to confirm, not something a migration should assert on your behalf. That list comes to you separately.
يضيف فهرس أنظمة معلومات المستشفيات: أحد عشر نظامًا، كل اسم مأخوذ من بياناتك نفسها. «رابسودي» غير مُدرج عمدًا لأنه محرّك التكامل لدى فريقكم التقني وليس نظامًا تشغّله المنشأة.

Step 5 — check, and what to do if it complains

5

2 minConfirm it took

Back in the SQL Editor, run this one line:

select name, hidden from use_cases order by sort_order;

You should get fifteen rows — eleven with hidden false, four true. In sort_order they come out in this order, which is not the order I have been saying them in: ADT, Medication Prescribe V1, Medication Prescribe V2, Medication Dispense V1, Medication Dispense V2, Rad Order, Rad Report, Lab Order, Lab Result, Clinical Notes, then the three hidden XD rows, then Vital Signs — visible, and last because it is the one you remembered later — then hidden Encounter History. Order before Report, and Order before Result, is the catalogue's existing numbering and not a fault.
If a file stops with a red error: nothing was committed — the database is exactly as it was before you pressed Run. Copy the error text and send it to me. Do not run the next file, and do not run the same one twice to see if it takes; the checks are there so that a half-finished apply cannot hide.

Every destructive thing that has already happened wrote a record of itself first, in docs/EVIDENCE/import-runs/ — the twenty-one merged organizations and the sixty-seven moved use-case rows are each held there in full, so any of it can be walked back row by row.

للتأكد، شغّل السطر المذكور أعلاه: يجب أن تظهر إحدى عشرة حالة استخدام ظاهرة وأربع مخفية. وإذا توقّف أي ملف برسالة خطأ حمراء فلم يُحفظ شيء، وقاعدة البيانات كما كانت تمامًا: انسخ نص الخطأ وأرسله لي، ولا تُشغّل الملف التالي.
